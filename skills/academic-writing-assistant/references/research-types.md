# Research Types

研究类型决定证据与结构，不由学科标签唯一确定。同一论文可以混合理论、实验、调查和定性材料，分别维护其主张边界。作者定义、已确认术语表与实际研究设计优先于通用偏好。

| 类型 | 主要证据 | 最常见的越界 |
|---|---|---|
| 方法与实验型 | 对照实验、基准测试、消融 | 单一条件结果推广为普遍有效 |
| 理论证明型 | 定义、假设、证明 | 丢失定理条件；把证明降格或把猜想升格 |
| 定性研究型 | 访谈、观察、文本编码 | 主题写成总体比例或因果效果 |
| 综述型 | 已读文献 | 未做系统检索却自称系统综述 |
| 定量观察与调查型 | 问卷、二手数据、队列 | 相关写成因果 |
| 人文与法学阐释型 | 史料、文本、法条、判例 | 阐释写成定论；应然写成实然 |
| 案例研究型 | 案例资料 | 分析性推广写成统计规律 |
| 设计与工程实现型 | 原型、仿真、试验、用户研究 | 实现了功能即声称已验证有效 |

## 方法与实验型

可按问题 → 方法 → 评估设置 → 结果 → 解释组织，使用实际给定对象、指标、对照和不确定性。神经网络、训练和消融仅在研究确实包含时使用。表格可读就实际查看，不用泛泛“请补数据”代替已有材料。

检查协议、单位、指标方向及结论范围是否对应。关键词命中只是线索，不证明章节完整或质量合格。

## 理论证明型

关注定义、假设、命题、证明依赖与适用范围。区分已给完整证明、证明纲要、经验观察和待证明猜想；不从“理论”标签推断证明完成，也不机械弱化已有证明。

摘要与结论保留定理必要条件。缺少推导步骤时指出具体依赖或缺口；不擅改锁定公式，不凭空补定理。可检查已给推导的局部一致性，但只报告实际进行的核查。

合成例：作者给定理“非空有限集合 S 上的实值函数 f 存在最小值”，并给出有限个函数值逐一比较的证明。摘要写“任意集合上的函数都存在最小值”时，应据此恢复“非空有限”和“实值”条件，按 L3 披露；不要求补准确率或消融实验。

## 定性研究型

组织问题、样本与情境、材料来源、实际分析过程、主题与原始材料支持、解释及边界。完成编码、双人复核、饱和、成员核查、伦理/同意等行为只能在作者提供时写。

访谈摘录与主题解释不是同一层证据。逐字引语按原文保留，删节/翻译按授权标示；解释定位到实际片段。没有逐例计数不写“大多数”，便利样本中的主题不推广为总体比例或因果效果。

合成例：一位受访者说“我更愿意自己找资料”，另一位说“我仍需要即时反馈”。可写两种体验并存，不能据此断言课程“显著提高所有学生自主学习能力”。

## 综述型

区分叙述性综述、范围综述、系统综述和定量合成，按实际执行方法写。没有给定检索库、日期、策略、筛选和纳入流程时，不自称系统检索；读过两份摘要不等于完成系统综述。

从实际材料建立“来源 → 对象/方法 → 结论 → 支持范围”的对照，组织共同点、分歧与缺口。不同研究的不同指标不能简单平均成总体效果；未做的荟萃分析、质量或偏倚评价不默认补齐。

合成例：两份摘要分别报告反馈可读性较高与部分参与者认为反馈笼统，可描述其关注点不同，不能写“文献一致证实效果”。仅摘要支持应明确标记，保留作者引用编号体系。

## 定量观察与调查型

问卷调查、二手数据回归、队列与横断面研究、计量分析等。组织研究问题或假设 → 数据来源与样本 → 变量与测量 → 分析方法与识别假设 → 结果 → 稳健性或敏感性分析 → 讨论。

因果表述的强度取决于设计与识别假设，而不是“回归”或“调查”标签本身：横断面相关不写成影响机制，有明确识别策略且作者给出依据时可按其假设表述。系数、标准误、置信区间、样本量与显著性水平属于锁定区；不补写未提供的稳健性检验、工具变量或控制变量。

合成例：作者报告“每周阅读时长与成绩呈正相关（r = 0.32，p < 0.01，N = 210，横断面问卷）”。不能改写为“增加阅读时长能显著提高成绩”；可写“二者呈正相关”，如需讨论可能机制，标为候选解释。

## 人文与法学阐释型

以史料、文本、法条与判例为证据的论证研究。按问题 → 材料与既有研究 → 分层论证 → 结论组织，不强制方法、实验或样本量章节。

区分材料本身说了什么、作者的阐释和作者的价值判断。直接引语、出处、版本、页码属于锁定区；阐释性限定（“或可”“似乎”“在此意义上”）是承重语言。法学中“应当/可以/不得”的规范效力不随润色改变，应然主张不写成现行规定。

合成例：作者据两封书信推测某人“可能已有离京打算”。润色后不能变成“他决意离京”，也不补写未见于材料的原因。

## 案例研究型

单案例或多案例研究的结论是分析性推广，不是统计推广。写清案例选择理由、资料来源（访谈、档案、观察）和分析过程；作者未提供的三角验证、编码流程不写成已完成。“管理启示”“政策建议”限定在案例所支持的情境中。

## 设计、开发与工程实现型

系统、算法、装置、软件、教学方案等设计类研究。组织需求或问题 → 设计方案与依据 → 实现 → 验证（试验、仿真、用户研究、案例应用）→ 局限。功能实现不等于有效性已被验证；“具有良好应用前景”需要验证材料支持。性能、用户满意度与可用性数据只写实际测得的结果。

## 混合与未列类型

遵循作者问题与结构，先确定每个主张对应哪类材料。艺术创作研究、政策分析、教学实践反思等其他类型同样先识别证据形式，再决定结构。无法判断结构时集中确认影响结果的少量信息，继续可做的表达改善。学科层面的提示见 [field-adapter.md](field-adapter.md)。
